# Q&A prep and glossary

## Likely questions
**Did you write the code?**
No — I directed it. Claude wrote the code and the Blender scripts. I wrote the brief, provided the references, made the design calls, playtested and gave feedback every round. The full history is on GitHub.

**So what was your contribution?**
The vision, the references, the art direction and the judgement: what's working, what's not, what matters most. The AI is fast but it can't feel the game. Every "this feels wrong" came from me playing it.

**How long did it take?**
Nine days, Nov 10–18, 27 versions. The first playable version took one evening.

**What was hardest?**
Making the character feel alive. The design is simple, so all the personality is in the motion. It took several rounds.

**Why Blender by script and not by hand?**
Repeatable and fast to change. Fixing the arms was changing a few numbers and re-running, not re-sculpting. Every model has a history in Git.

**What's Frutiger Aero?**
A mid-2000s design style (Windows Vista/7, early iPhone, Wii era): glossy, glassy, aqua and green, nature and technology together, optimistic. I wanted the tasteful version — beautiful and natural, not glass bubbles everywhere.

**Is anything copied from Wii Sports Resort?**
No. Same *feeling* — connected island, stumbling onto activities. The layout, names, character and assets are original.

**Are the assets licensed?**
Yes. Textures are CC0 from Poly Haven, sounds are CC0 or public domain, all logged in `LICENSES.md`. Every 3D model was made for this project.

**What would you do next?**
Finish the story at the summit, playtest with other people, and split the build so it loads faster.

**What did you learn about working with AI?**
Clear inputs get clear outputs. References beat descriptions, and specific feedback with a recording gets fixed in one round. You still have to check its work — it will say something's done when it isn't.

## Glossary (terms to use confidently)
| Term | Meaning |
|---|---|
| **Three.js** | JavaScript library for drawing 3D in a web browser |
| **Vite** | Tool that runs the game while developing and bundles it for release |
| **GLB / glTF** | The standard file format for 3D models on the web |
| **Blender Python (bpy)** | Controlling Blender with code instead of the mouse |
| **Procedural** | Generated by rules/code instead of made by hand (the terrain, the animation) |
| **Rig / bones / weights** | The skeleton inside a model, and how much each bone moves each part of the skin |
| **Spring (damped)** | Math that makes a value chase its target with a little overshoot and settle — gives the bouncy, alive feel |
| **Squash and stretch** | Classic animation principle: things compress on impact and stretch with speed |
| **Shader** | A small program on the graphics card that decides how surfaces look (water, grass, snow) |
| **Bloom / depth of field / colour grade** | Post-processing: glow on bright areas, blurred background, overall colour mood |
| **CC0** | "No rights reserved" licence — free to use for anything |
| **CI/CD, GitHub Actions** | Automatic build-and-publish every time code is pushed |
| **GitHub Pages** | Free hosting for a website straight from a GitHub repo |
| **Headless browser** | A browser with no window, used by scripts to take screenshots and run tests |
| **Smoke test** | A quick automated run-through to check nothing is broken |
| **Coding agent** | An AI that doesn't just answer — it writes files, runs code, tests and iterates |
